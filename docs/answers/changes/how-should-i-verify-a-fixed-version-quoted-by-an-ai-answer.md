# How should I verify a fixed version quoted by an AI answer?

Treat a quoted fixed version as a claim to verify against a dated primary advisory for the exact product and release line. Two of 148 eligible PHP2Shell answers captured on 23 October 2026 gave a wrong fixed version. A fluent version statement is therefore insufficient evidence for deciding that a live system has been fixed.

## What we measured

**Measured.** The [PHP2Shell study method](https://doi.org/10.5281/zenodo.23586713) assessed incident answers and their sources against a dated reference record. It planned 150 observations and retained 148 eligible answers after two exclusions on 23 October 2026. The two wrong fixed-version answers are the event relevant here. They are also the same two answers in the study's WordPress-error category, so those labels must not be added into a four-answer total. This is a record of answer errors, not a current list of affected or safe versions.

## What this means for you

**Reasoned.** Write down the quoted version before checking it. Identify the product, component and release line to which the answer attaches the claim. Then open the primary advisory or official release record that actually supports that statement. An answer linking a genuine source can still attach a version to the wrong scope.

Keep the source wording beside the AI wording. Look for an explicit relationship between the reported issue and the release being discussed. If the source names a planned change, an investigation or a different product branch, retain that state rather than converting it into a completed fix. If the primary source does not resolve the version claim, the result of this check is unresolved.

Record the source's revision date and the time of your review. A later advisory can change the present assessment without rewriting what an earlier captured answer said. Preserve both references when you explain a correction.

The final operational decision belongs with the responsible technical team using current product evidence. This page gives no version number to install, exploitation detail or repair instruction; it explains how to assess the provenance of the quoted claim.

- **For an answer reviewer:** match the version to its product and dated source before accepting the conclusion.
- **For a vendor:** make the release state explicit in the official statement.
- **For a publisher:** correct the narrow version claim without adding an unsupported remedy.
