# Does allowing GPTBot make a site appear in ChatGPT search?

No. GPTBot is OpenAI's training crawler, while OAI-SearchBot supports search; OpenAI documents their controls as independent. Allowing GPTBot does not set your search permission or secure a place in an answer. In our construction capture of 22 September 2026, Procore appeared by name in 23 out of 30 ChatGPT responses. That observed output is separate from a test of either crawler setting.

## What we measured

**Reported.** OpenAI's [bot guide](https://developers.openai.com/api/docs/bots), read on 29 October 2026, distinguishes GPTBot's training purpose from OAI-SearchBot's search purpose. A site owner can allow one while restricting the other. Its [search help article](https://help.openai.com/en/articles/9237897-searching-the-web-with-chatgpt), read the same day, describes searchbot access and host permission for the published searchbot addresses as eligibility checks, without a guarantee of placement.

**Measured.** The [September Index](https://doi.org/10.5281/zenodo.22907695) supplies ten construction buyer questions and three ChatGPT runs per question. All 30 responses were retained and 23 named Procore. That engine-presence field does not record whether a search ran, which robot requested a page or the page's crawler permissions.

The naming observations cannot establish that allowing GPTBot caused a search appearance.

## What this means for you

**Reasoned.** Read the robot's purpose. If a change request concerns future training collection, GPTBot is the name in OpenAI's documentation. A request about search access concerns OAI-SearchBot instead. Writing allow OpenAI in a handover leaves that choice unresolved.

For the Procore example, the counting event is a name in a retained answer. The 23 appearances are not 23 recorded requests to Procore's site. A report that relabels them crawler visits would be answering a different question from the one the Index measured.

If you intend to permit search while restricting training, ask the site maintainer to inspect the two rules separately. OpenAI's published distinction gives that request a precise scope. The search help also names host-level permission for the searchbot's published addresses, so the robots instruction alone does not establish that the host accepts the traffic.

Do not use a before-and-after Procore naming total as a substitute for a permission check. The September capture has no paired GPTBot access experiment. A different answer on a later refresh therefore needs its own observation and cannot, by itself, identify a crawler-setting effect.

OpenAI also names ChatGPT-User for user-directed requests. Its purpose is distinct from automatic search crawling in the bot guide. If a colleague supplied a direct URL to ChatGPT, retain that context rather than treating the resulting page retrieval as another spelling of OAI-SearchBot access.
