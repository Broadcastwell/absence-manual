# Can dental practice software integrate with ChatGPT?

Dentally's practice and partner FAQs document API access, a possible dental-system side of a custom connection; neither inspected FAQ confirms a ready-made ChatGPT integration. You need the actual assistant route as well. In our Agent Gap dental capture on 6 October 2026, 12 of 15 initial website tasks reached their public endpoint. Those visits did not connect to practice records or test an assistant workflow.

## What we measured

**Measured.** The [Agent Gap protocol](https://doi.org/10.5281/zenodo.23197560) assigned three public-website tasks to each of five dental-software vendors. Twelve reached the requested endpoint on 6 October 2026. A reached page could explain a product or offer a demo; it did not grant access to appointments, patients or treatment records.

**Reported.** Dentally's [practice FAQ, dated 8 September 2026](https://help.dentally.com/en/articles/15174786-nexgen-api-practice-faqs), says a practice can obtain NexGen API access for its own use. It separately says partners authenticate with Dentally and have their data requirements checked. We read that page on 29 October, without creating access or reading a practice account.

The [partner FAQ, dated 7 August 2026](https://help.dentally.com/en/articles/15956843-dentally-partner-api-faq-s), describes an account review, sandbox access and a reviewed demonstration before production access. These are supplier-published stages for a partner build. They are not evidence that a ChatGPT connector has completed them.

## What this means for you

**Reasoned.** Separate the two routes. Your practice's own API access and a third party's approved partner access have different owners. The September FAQ explicitly distinguishes them; a broad statement that only partners can ever obtain access would miss the practice-use provision.

For a proposed ChatGPT connection, establish which product performs the dental request and which component sends the result to the assistant. The Dentally FAQ alone does not identify that assistant component. It cannot confirm a tool that reads appointments or writes a booking simply because the practice has API access.

The migration date matters. Dentally's August FAQ describes a transition from v1 to NexGen, with parity targeted for the end of 2026. That is a target, not a completed migration proven here. A supplier showing an older workflow needs to identify which API version its demonstration actually uses.

Do not confuse a marketplace plan with a live permission screen. The August partner FAQ marks the practice-approval flow through a future in-app marketplace as not yet built. A proposal relying on that flow needs current evidence that it is available, rather than a screenshot of the roadmap text.
