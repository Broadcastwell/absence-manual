# Can transportation software integrate with ChatGPT?

Finding a freight-software website does not prove a ChatGPT connection. Alvys separately reports beta MCP access for ChatGPT; our [Agent Gap study](https://doi.org/10.5281/zenodo.23197560) reached 11 of 15 initial transportation-software website tasks on 6 October 2026, measuring the public path rather than that account route.

## What we measured

**Reported.** Alvys's [Intelligence page](https://alvys.com/features/alvys-intelligence), read on 29 October 2026, names ChatGPT among the clients for its MCP Server Access. The inspected section lists load search, invoice status, driver availability and tracking history, and labels the access beta.

**Measured.** The [Agent Gap study design](https://doi.org/10.5281/zenodo.23197560) for the transportation-management-systems category comprised five vendors, with an initial description, pricing and demo-path task for each. Eleven of the fifteen initial tasks reached their target. The category-level total counts public endpoints reached; it is not a result for Alvys's MCP implementation.

**Reasoned.** A transport-system account contains operational records that a public pricing page does not. Our website tasks cannot establish the beta connector's permissions, write actions or behavior in your account.

## What this means for you

Use the action names. A dispatcher asking for tracking history has a request named in the inspected Alvys section. Creating or changing a load is a different request; it should not be inferred from the word “search” or from the separate AI features described elsewhere on the same product page.

The invoice-status example concerns an existing billing record. It should not be described as authority to edit the invoice, approve a charge or send it to a customer. Those are distinct operational actions, and the short MCP section does not specify their permission boundaries. A proposal that groups them under one “billing integration” label loses the distinction that made the status example checkable.

For a provider demonstration, keep the beta label with the named client and requested task. A tracking-history response should identify which account and load it concerns, whereas our Agent Gap receipt identifies a public vendor endpoint. If you later compare the two records, preserve their original units: one account task and one public-site task are different observations, even when the same vendor name appears on both.
